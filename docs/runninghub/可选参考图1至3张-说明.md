# 海螺 H3 人物替换流 · 参考图 1~3 张可选（v1.6）

源文件：`海螺H3 人物替换专用流v1.5.json`（未改动）
新文件：`海螺H3 人物替换专用流v1.6-可选参考图1至3张.json`

## 一、为什么要改

v1.5 把三张参考图硬接在 `MiniMaxH3ReferenceToVideo`（节点 208）上，三张图分别是：

| 槽位 | 来源节点 | 提示词里的角色 |
|---|---|---|
| `ref_image_0` | 215 LoadImage | `<Picture 1>` 主角 |
| `ref_image_1` | 218 LoadImage | `<Picture 2>` 配角 |
| `ref_image_2` | 221 LoadImage | `<Picture 3>` 场景 |

RunningHub 的 `nodeInfoList` 只能改节点里的**参数值**，不能增删连线、也不能切换节点的 bypass 状态。所以"这次用几张图"没法靠 API 改拓扑。

## 二、v1.6 的做法

用 **三个条件变体 + 惰性开关**：需要几张图，就走那一条支路，**其余支路不执行**（连 LoadImage 都不会读盘）。

```
215/218/221 (LoadImage) ─┬→ 208 条件·1张 ─┐
                          ├→ 700 条件·2张 ─┼→ 702 开关 ─→ 703 开关 ─┬→ 191 BasicGuider (一采)
                          └→ 701 条件·3张 ─┘                          └→ 183 BasicGuider (二采)

706 EmptyMiniMaxH3LatentAV ─→ 196 SamplerCustomAdvanced.latent_image
```

改动清单：

1. **208 变成"1 张"变体**：只保留 `ref_image_0`；摘掉 `ref_image_1/2`，同时摘掉旧版"最多 6 图"残留的 `ref_image_3/4/5`（615/618/614 → 613/616/617 已旁路）。
2. **新增 700「条件 · 2 张参考图」**：接 215 + 218。
3. **新增 701「条件 · 3 张参考图」**：接 215 + 218 + 221。
4. **新增 702 / 703 `LazySwitchKJ`** 惰性开关串联，只求解被选中的那一支。
5. **新增 704 / 705 `PrimitiveBoolean`**，作为对外暴露的两个 API 参数。
6. **新增 706 `EmptyMiniMaxH3LatentAV`**：原来首采的 latent 由 208 提供，但 208 在 2/3 张时不会执行，所以把 latent 解耦出来（调用的就是同一个 `_empty_av_latent(width,height,length)`，输出完全一致）。
7. 一采/二采续接节点 588/590 本身处于 bypass，透传时按类型精确匹配，而开关输出是通配类型 `*`，匹配不到 `CONDITIONING`，因此 **703 直连 191 / 183 两个 `BasicGuider`**，不再借道它们。

## 三、API 参数

| 张数 | 704 `value` | 705 `value` | 实际用到的 Picture |
|---|---|---|---|
| 1 张 | `false` | `false` | `<Picture 1>` |
| 2 张 | `true` | `false` | `<Picture 1>`、`<Picture 2>` |
| 3 张 | `true` | `true` | `<Picture 1>`、`<Picture 2>`、`<Picture 3>` |

只按 1→2→3 顺序启用；**不支持**跳过第 2 张只启用第 3 张。

## 四、已验证的内容

- 连线完整性：301 条 link 全部端点一致，无悬空引用。
- 执行范围模拟（从输出节点反向遍历，惰性开关只走选中分支）：

| 参数 | 执行的条件节点 | 执行的 LoadImage | 合计节点 |
|---|---|---|---|
| 704=false, 705=false | 208 | 215 | 54 |
| 704=true, 705=false | 700 | 215, 218 | 56 |
| 704=true, 705=true | 701 | 215, 218, 221 | 57 |

即：**用 1 张时，另外两张图既不加载也不编码**，不会因为缺图或塞了占位图而影响结果。

## 五、注意事项

1. **提示词里的 `<Picture N>` 必须和启用的张数对上**，否则模型看到的图和文字对不上。
2. **未启用的 LoadImage 不会执行**，但 RunningHub 侧仍可能对未填的图片字段做预校验，建议 3 个 `image` 字段都传（未启用的随便传一张，不影响结果）。
3. `LazySwitchKJ` 来自 KJNodes（这个流本来就在用：`ResizeImagesByShorterEdge`、`ImageFromBatch`、`ImageBatchMulti`）。若 RunningHub 的 KJNodes 版本过旧导致节点报红，换成任意"双分支开关"即可，只需保持输入名 `switch` / `on_true` / `on_false`。
4. 参考图4/5/6（节点 615/618/614、613/616/617）仍是旁路状态，已不再接入，留作以后扩展。
5. 原 `v1.5` 文件保持不动，可随时回滚对比。
