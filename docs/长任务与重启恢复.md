# 长任务与重启恢复

视频生成是长任务（RunningHub 上跑一条 5 秒的片子要 7 分钟上下），中间很可能发生的事：
用户把本地服务关掉了、机器重启了、浏览器刷新了。这份文档说清楚各种情况下会发生什么。

## 记录存在哪

每条生成记录都写在数据目录的 `history.json` 里（多人模式是 `users/<账号 id>/history.json`），
提交成功的那一刻就落盘了。记录里的 `id` 就是平台上的任务 id，所以重启之后还能接着查。

```jsonc
{
  "id": "2116829994726813698",      // 平台的任务 id
  "provider": "runninghub",
  "status": "in_progress",
  "rhKeyId": "kd7c7e2ce50",         // 占的是哪个 Key 的并发位子
  "rhSite": "ai",
  "rhPreview": { "url": "wss://…", "clientId": "…" },  // 实时预览通道的地址
  "remoteUrl": "https://…/xxx.mp4",  // 平台给的结果地址
  "localFile": "2116829994726813698.mp4"                // 存到本机之后
}
```

## 重启之后会发生什么

服务一启动就做三件事（`server.js` → `openAllSpaces()` → `startPolling()`）：

1. **把所有空间都打开**（本机的 + 每个成员的）。以前要等第一个请求进来才看得到这些记录，
   用户重启服务后没打开页面，任务就没人管了。
2. **把上次留下的记录理一遍**（`settleHistory`）：
   - `direct` 的（图片、语音这类一次请求直接返回结果的）跟着进程走，服务重启后没法接着等，
     标成「生成已中断」；
   - 平台已经下线的（以前的 Flatkey、OpenRouter）标成「该平台已停用」；
   - **还在平台上跑的任务保持进行中**，接着查。
3. **给「跑完了但文件没存下来」的记录一次新机会**（`resumePending`）：以前失败满 6 次就永远不试了，
   会一直卡在「保存失败」；重启就是一次新的机会。

然后轮询循环（每 2 秒扫一遍）把状态、结果都补齐：查到了完成就把文件下载到本机
（`data/videos/` 等目录），缩略图、积分对账也跟着走。

**实时预览**（RunningHub 的 `kj_preview_override`）在重启后也会重连——通道地址记在记录上的 `rhPreview` 里。
官方把这条通道标注为「not recommended currently, unstable」，所以连不上也不影响主流程。

## 每个平台的行为

| 平台 | 任务 id | 重启后 |
|---|---|---|
| RunningHub | 平台的任务 id | 接着查；Key 的并发占位按 `rhKeyId` 还原（不会重启一次就多派一单） |
| 火山方舟 | 平台的任务 id | 接着查 |
| MiniMax | 平台的任务 id | 接着查（只能查到 7 天以内的任务） |
| AutoDL.art | 平台的任务 id | 接着查 |
| 图片 / 语音（direct） | 无 | 标成「生成已中断」，需要重新生成 |

## 边界

- **6 小时上限**：任务提交超过 6 小时还没结果，就不再自动查了（`INNATE_PENDING_LIMIT_MS` 可改）。
  判断顺序是「先查一次再判超时」——服务关了很久再启动，任务其实早就跑完的，照样能拿到结果。
- **结果地址会过期**：平台的下载地址放不了太久（AutoDL 的文档明说过）。所以结果一拿到就存到本机，
  记录不依赖远端地址还能不能用。
- **重启时正在下载的**：下载是写到一半的临时文件，重启后从头再下一次，不会留下半个文件。
- **已经跑完但文件没下下来的**：现在会自动重下；页面上也有「重新保存」按钮可以手动触发。

## 一个真实踩过的坑

RunningHub 的结果放在对象存储上（`rh-hk-images-….myqcloud.com`），不是平台自己的域名，
所以 `platform.baseUrl` 是空的。下载时原来写的是 `new URL(url, platform.baseUrl)`——
拿空串当基准，`new URL` 直接抛 `Invalid URL`，**每一个 RunningHub 的结果都下不下来**。
任务在平台上跑完了、钱也花了（一次 86 币），本地却一个文件都没有，还显示「保存失败」。
现在改成：平台没给域名就用地址本身，只有地址是相对路径时才拿平台域名去拼。

回归测试在 `test/resume.test.js`（地址拼接 + 恢复逻辑）和 `test/restart.test.js`
（真把服务杀掉再拉起来，确认任务接着跑、结果接着存）。
